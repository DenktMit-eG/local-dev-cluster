# Spring Boot Configuration

The setup script generates an `application.yaml` at the repository root that wires `spring-kafka` and
`kafka-avro-serializer` against the local cluster. The file embeds the keystore password from
`secrets/kafka/userpass.txt` directly, which is why it is local to your machine and must not be committed.

## Generate it

```bash
./scripts/kind_setup.sh get-secrets
```

The script also runs as part of `earthly +kind-create-local`, so a fresh `earthly +kind-create-local` produces both the
cluster and the `application.yaml`.

## What the file contains

```yaml
spring:
  kafka:
    bootstrap-servers: bootstrap.local.lgc:9094
    security:
      protocol: SSL
    ssl:
      key-store-type: PKCS12
      key-store-location: file:///abs/path/to/secrets/kafka/user.p12
      key-store-password: <contents of secrets/kafka/userpass.txt>
      trust-store-type: PEM
      trust-store-location: file:///abs/path/to/secrets/kafka/ca.crt
    properties:
      auto.register.schemas: true
      schema.registry.url: https://sr.local.lgc
      ssl.client.auth: true
```

| Property                      | Why it is set                                                     |
|-------------------------------|-------------------------------------------------------------------|
| `bootstrap-servers`           | Hits the Kafka external listener via Traefik                      |
| `security.protocol: SSL`      | mTLS, with `ssl.client.auth: true` requiring a client certificate |
| `key-store-*`                 | Points at the PKCS12 generated by Strimzi for `kafka-super-user`  |
| `trust-store-*`               | PEM bundle of the mkcert root and the Strimzi cluster CA          |
| `auto.register.schemas: true` | Lets the Avro serializer register schemas during development      |
| `schema.registry.url`         | Confluent Schema Registry behind Traefik HTTPS                    |

The schema registry call uses the JVM trust store (it is plain HTTPS, not Kafka mTLS). Make sure the JVM trusts the
mkcert root, otherwise the registry call fails before any Kafka traffic is exchanged. `mkcert -install` typically takes
care of that on macOS and Linux JDKs that share the system trust store; if not, import `secrets/kafka/ca.crt` (or the
mkcert root directly) into the JVM keystore.

## Use it

Set the environment variable before starting the application:

```bash
export SPRING_CONFIG_ADDITIONAL_LOCATION=file://${PWD}/application.yaml
```

You can also point Spring at it through `--spring.config.additional-location` or by importing it from your own
`application.yaml` with `spring.config.import: file:./application.yaml`. The first form is what `scripts/kind_setup.sh`
prints to stdout after generation.

## Regenerating after a recreate

`kind delete cluster && earthly +kind-create-local` issues a fresh `kafka-super-user` Secret with new keystore contents
and a new password. The old `application.yaml` and `secrets/kafka/` files no longer match the broker. Always rerun
`get-secrets` after a recreate; the script overwrites both atomically.
